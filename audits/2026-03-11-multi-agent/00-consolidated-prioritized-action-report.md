## Executive Summary

The app currently has **release-blocking security and correctness issues** (IPC trust boundaries, frontend/backend contract mismatches, progress forgery, and XP duplication) that can both break core flows and undermine adaptive learning integrity. In parallel, prompt/context architecture has both **over-pruning** (loss of personalization) and **under-pruning** (token bloat), creating avoidable quality and cost issues.

## P0: Immediate Blockers (Fix First)

1. **Close IPC exfiltration and trust-boundary vulnerabilities.**
   - Block arbitrary file path ingestion in `submit_project`.
   - Remove client-authoritative grading/progress/XP writes.
   - Move API key storage/retrieval to OS keychain patterns; remove plaintext key retrieval command.
   - Why now: high-impact security exposure and integrity compromise.

2. **Repair frontend/backend contracts for lesson, quiz, project, and gamification.**
   - Enforce shared typed payload schemas (`serde` + TypeScript runtime validation).
   - Make `get_lesson` and `get_quiz` return structured objects expected by UI.
   - Align `submit_project`, `get_projects`, and gamification state shapes.
   - Why now: current mismatches can crash runtime or render invalid states.

3. **Stop XP and mastery inflation exploits.**
   - Remove duplicate XP award paths (single authoritative backend award).
   - Prevent repeated completion triggers from awarding XP again.
   - Replace prereq gate `mastery_score > 0` with thresholded gating (for example `>= 0.8` + minimum attempts).
   - Why now: progression and motivation systems are currently gameable and can destabilize learning paths.

4. **Restore failing verification guardrails.**
   - Add ESLint v9 flat config; re-enable lint in CI.
   - Resolve Tauri `macos-private-api` feature/allowlist mismatch so Rust checks/tests run.
   - Why now: cannot safely regress-proof upcoming fixes without these checks.

## P1: High-Priority Product Quality and Learning Integrity

1. **Fix diagnostic and error-state reliability.**
   - Eliminate blank-screen states and race conditions in diagnostic flow.
   - Replace silent catch blocks with explicit user-facing errors and retry actions.

2. **Stabilize grading fairness for adult learners.**
   - Add tolerance/equivalence logic for numeric/text answers.
   - Avoid punitive defaults on parser/model formatting failures; use `ungraded/retry` states.
   - Ensure question types generated by prompt are strictly limited to supported types.

3. **Improve adaptive context quality.**
   - Persist and pass richer learner context (objectives, difficulty tier, error patterns, prerequisite vector).
   - Wire interleaving/review engine into active session generation.

4. **Accessibility and usability corrections.**
   - Keyboard-operable interactions for path cards and skill tree.
   - Proper labels/ARIA for icon buttons and form controls; add live regions for async status.
   - Address low-contrast text token usage.

## P1: Prompt/Token Optimization Without Learning Regression

1. **Rebalance pruning strategy.**
   - Too aggressive today: cache/context reuse suppresses personalization.
   - Not aggressive enough today: one large multi-mode prompt sent broadly.

2. **Adopt mode-specific prompt composition.**
   - Split prompt into `shared + mode-specific` fragments and only send relevant sections.
   - Expected reduction from agent estimate: ~800-1000 input tokens/call.

3. **Context-aware cache keys and invalidation.**
   - Key cache by model + coarse mastery/attempt buckets.
   - Invalidate on mastery inflection and model setting changes.

4. **Token budget instrumentation and control.**
   - Add per-mode max-token caps.
   - Persist `input_tokens`, `output_tokens`, and `stop_reason` for budget tuning.

5. **Constrain attachment token/cost spikes.**
   - Hard file size caps and preflight warnings.
   - Optional page-limited analysis mode for large docs.

## P2: UX and Curriculum Enhancements

1. Improve navigation discoverability for key routes (`/diagnostic`, `/path/:domainId`).
2. Add mobile-first navigation mode (collapsible sidebar, denser but accessible top bar behavior).
3. Replace confidence-only diagnostic with competency probes mapped to placement.
4. Expand progress history from synthetic snapshots to true historical traces.
